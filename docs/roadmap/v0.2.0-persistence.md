# v0.2.0 — Persistence 📋 Planned

**Theme:** Your work survives a refresh. Threads are saved, named, and reloadable;
the agent remembers the conversation.

## Goal & why

Today threads live only in `useThreads` React state — reload the page and
everything is gone, and the sidebar "recents" are placeholders. This is the single
biggest gap between "demo" and "feels like a product." The agent already has
Mastra `Memory` wired; this version makes it real end to end.

## Scope

- **Server-side conversation memory** — give each thread a stable
  `threadId` + `resourceId` and pass them through `agent.stream(...)` so Mastra
  persists the conversation in `mastra.db`. Reloading a thread replays its real
  history instead of starting blank.
- **Thread list persistence** — the web app loads existing threads on mount (via
  the Mastra client) and reflects them in the sidebar **recents** (real titles +
  timestamps, not mock data).
- **Saved & named threads**:
  - **Auto-title** a thread from its first question.
  - **Rename** and **delete** a thread.
  - Persist the active-thread selection across reloads.
- **Empty / loading / error states** for thread history (loading spinner,
  "no threads yet," failed-load retry).

## Out of scope

- Multi-user / auth — threads are still single-user/local (see v0.x icebox).
- Sharing / permalinks / export of a whole thread — later.
- Full-text search across threads — later (a simple title filter is enough here).

## Technical notes

- Mastra `Memory` + thread/resource IDs is the intended persistence path; prefer
  it over inventing a parallel store. Confirm the client API for **listing** and
  **fetching** a thread's messages in this Mastra version, and map those into the
  existing `Thread`/message shapes in `types.ts`.
- `mastra.db` already holds Mastra's conversation/telemetry storage (it's
  gitignored and distinct from `warehouse.db`) — this version starts using it for
  real.
- Keep `useThreads`' streaming/soft-stop behavior intact; persistence wraps it
  (load on mount, save on create/rename/delete), it doesn't replace it.
- Reconstruct a reloaded thread's **thinking timeline + result cards** from stored
  tool calls/results where available; if only text is persisted, degrade
  gracefully to the answer text.

## Done when

- Create a thread, ask a question, **refresh** → the thread and its full history
  (answer, thinking steps, result card) are still there.
- The sidebar recents list real threads; selecting one reloads its conversation.
- Rename and delete work and persist.
