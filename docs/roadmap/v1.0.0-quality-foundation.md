# v1.0.0 — Quality foundation ✅ Shipped

**Theme:** The prototype graduates to a real, tested product. Add a real test
runner and CI so every change is checked automatically — the engineering work
deliberately deferred while the feature track (v0.2–v0.5) came together, paid down
to mark **1.0**: Dex is no longer a learning prototype.

## Goal

Make correctness **automatic and enforced** — a real test runner in both apps
plus CI on every push/PR — so the codebase is solid before the big builds.

## Why

The feature track is done: persistence (v0.2), live warehouses (v0.3), the semantic
layer (v0.4), and richer results (v0.5) have all landed — but verification is still
manual (`typecheck` +
`lint` + `build` + the agent's `npm run smoke`). That was fine for the early push;
it's brittle now that the surface is this wide. **1.0** is where the prototype
stops being a prototype: correctness becomes **automatic and enforced**, so the
codebase is solid before the big **v2.0 NotebookEditor** build — without regressing
the v0.1 contract.

## Scope

- **Web unit tests — Vitest + React Testing Library** (jsdom env):
  - `useThreads` stream mapping — feed a scripted sequence of Mastra chunks
    (`text-delta`, `tool-call`, `tool-result`, `finish`) through a mocked
    `processDataStream` and assert the resulting thread/message state (answer
    text, the thinking timeline, the result card).
  - `isSqlResult` shape detection (`types.ts`) — positive/negative cases,
    including the column-classification added in v0.5.
  - `ResultCard` rendering — table, the chart-type selection, and the inferred
    default (v0.5); CSV/clipboard export.
  - `Composer` — send on submit, and the **Stop** affordance while streaming.
  - Persistence (v0.2) — load-on-mount, auto-title, and the rename/delete paths.
- **Agent tests — promote `db/smoke.ts` into real tests** (still **no LLM**):
  - `assertReadOnly` — accepts `SELECT`/`WITH`; rejects DML/DDL, multiple
    statements, comments-only, and empty input.
  - The **connector interface** (v0.3) — `listTables` / `describeTable` /
    `runReadOnlySql` against a freshly seeded temp SQLite `warehouse.db` (the
    no-setup default path); the Postgres connector behind a guard/skip when no
    test database is configured.
  - The **semantic-layer compiler** (v0.4) — a known semantic query compiles to
    the expected SQL, runs against the seeded sample, and the compiled SQL still
    passes `assertReadOnly`.
  - Pick the lightest runner that fits the agent's setup (Vitest, or
    `node:test`); keep `npm run smoke` working as the quick manual check.
- **CI — GitHub Actions** (`.github/workflows/ci.yml`), on push + PR:
  - Root: `format:check`, `typecheck` (both apps), `lint`.
  - Web: `build`, unit tests.
  - Agent: `seed` then tests / `smoke`.
  - Install each app separately (they're standalone, non-workspace projects); use
    npm caching.
- **Scripts** — add `test` (and `test:watch`) to each app and a root `test` that
  delegates into both.

## Out of scope

- E2E / browser tests (Playwright) — persistence (v0.2) already gives stable state
  to assert against, but full E2E stays a follow-up after 1.0 (revisit with v2.0).
- Coverage gates / required-check enforcement — start by making CI _exist_ and be
  green; tighten later.
- Any product behavior change — this version adds no features.

## Technical notes

- Vitest fits the existing Vite setup with near-zero config; reuse
  `resolve.tsconfigPaths` so tests can import via `@/`.
- Keep all agent tests LLM-free (the v0.1 split of `db/queries.ts` from `tools/`
  exists precisely for this).
- The pre-push hook can stay as `typecheck + lint`; CI is the backstop that also
  runs the test + build matrix.

## Acceptance criteria

- [x] `npm test` passes locally in **both** apps (web Vitest/RTL; agent LLM-free
      `node:test`).
- [x] A PR shows a **green CI** check running `format:check` + `typecheck` +
      `lint` + `build` + tests for both apps (`.github/workflows/ci.yml`).
- [x] `useThreads` chunk-mapping and `assertReadOnly` each have tests that **fail
      on regression**.
- [x] The semantic compiler + connector interface are covered by LLM-free tests;
      `npm run smoke` still works as the quick manual check.
