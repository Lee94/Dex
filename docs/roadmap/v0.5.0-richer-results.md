# v0.5.0 — Richer results 📋 Planned

**Theme:** Make the answer itself better to look at. Choose how a result is
visualized, support time-series, and let people take the data with them.

## Goal & why

v0.1 ships exactly one auto-chosen visualization per result (a table, or a bar
chart for two-column numeric data). Real analysis needs more: a revenue-over-time
question wants a **line**, a comparison wants a **bar**, and sometimes you just
want the **table** or the raw numbers. This version puts that choice in the user's
hands and adds the obvious missing affordance — **export**.

## Scope

- **Chart-type selection** — a control on `ResultCard` to switch between
  **table / bar / line / area** for any compatible result, with a sensible
  **inferred default** (e.g. a date/time first column → line).
- **Time-series support** — detect a temporal dimension and render an ordered
  line/area chart (the current bar chart assumes categorical x).
- **Better defaults & detection** — extend the `isSqlResult` shape logic in
  `types.ts` to classify columns (temporal / categorical / numeric) and pick the
  default chart from that.
- **Export** — copy a result table to the clipboard and **download as CSV**;
  optionally copy the underlying SQL.
- **Result-card polish** — number/date formatting, long-table scroll/virtualize,
  empty-result and "too many rows" states.

## Out of scope

- A full pivot/aggregation builder — the agent still shapes the data via SQL.
- Saved/pinned chart configs per thread (depends on v0.2 persistence; revisit
  after).
- Heavy BI features (drill-down, cross-filtering) — that's the Canvas/notebook
  direction, not here.

## Technical notes

- **Charting decision:** keep the hand-rolled SVG approach (matches the Blueprint
  design and the existing bar chart, zero deps) **or** adopt a small lib. Lean
  toward extending the SVG primitives first; only pull in a dependency if
  line/area + axes get unwieldy. Either way, colors come from `--dex-chart-*`
  tokens — **no hardcoded hex**.
- The chart-type toggle is per-result UI state; once v0.2 persistence exists, the
  selected type can be remembered per result.
- Keep the table the universal fallback — any result must be viewable as a table.

## Done when

- Any result can be switched between table / bar / line / area, with a good
  default inferred from the data.
- A monthly-revenue question renders an ordered line chart.
- A result can be exported to CSV / copied to the clipboard.
