# v0.5.0 — Live warehouses 📋 Planned

**Theme:** Point Dex at real data. Connect to a live Postgres warehouse behind a
clean connector interface, and add an endorsed/semantic layer so the agent answers
with trusted definitions.

## Goal & why

So far the agent only queries the bundled SQLite sample (`warehouse.db`). The
whole point of a Threads tool is asking questions of **your** data. This version
generalizes the data layer to real connections (starting with Postgres) and adds a
thin **semantic layer** so the agent prefers curated, "endorsed" metrics and
datasets over ad-hoc SQL.

## Scope

- **Connector interface** — refactor `db/queries.ts` behind a small interface
  (`listTables` / `describeTable` / `runReadOnlySql`) with two implementations:
  the existing **SQLite** (sample) and a new **Postgres** connector. The three
  tools (`list_tables`, `describe_table`, `run_sql`) talk to the active connector.
- **Connection management** — configure a connection via env/secrets
  (host/db/user/password/ssl); select which connection a thread uses. **Never**
  commit credentials.
- **Real-DB introspection** — implement `listTables`/`describeTable` over
  `information_schema` for Postgres; keep the output shape the tools/UI already
  expect.
- **Read-only enforcement, hardened** — `assertReadOnly` still gates every query,
  **and** connect with a read-only DB role + statement timeout / row caps as
  defense in depth.
- **Endorsed / semantic layer** — a small curated catalog of named metrics &
  datasets (trusted definitions, descriptions, canonical SQL) surfaced to the
  agent so answers use them when they fit; a way to mark something "endorsed."

## Out of scope

- BigQuery / Snowflake / DuckDB — once the connector interface exists they're
  additive; not in this version (icebox).
- A full semantic-model spec (joins, governance, lineage) — start with a flat,
  hand-authored catalog of metrics/datasets.
- Multi-tenant secret management — single-user/local secrets for now.

## Technical notes

- Lead with the **connector seam**: the v0.1 decision to keep `db/queries.ts`
  separate from `tools/` is what makes this a contained refactor — the tools and
  the entire web UI shouldn't need to change.
- Choose a maintained Postgres client; keep parameterization/escaping centralized
  in the connector. The read-only guard runs **before** the query reaches any
  connector.
- The semantic catalog can start as a typed config the agent's instructions/tools
  reference; expose "endorsed" status to the UI later (a Pill already exists).
- Update `npm run smoke` to cover the connector interface (SQLite path stays the
  no-setup default).

## Done when

- With a Postgres connection configured, asking a question runs against the live
  warehouse (introspection + read-only query) and streams a result card.
- The SQLite sample still works with zero setup (default connector).
- The agent can answer using an endorsed metric/dataset definition when one
  applies.
