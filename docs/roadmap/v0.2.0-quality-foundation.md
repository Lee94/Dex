# v0.2.0 — Quality foundation 📋 Planned

**Theme:** Make the prototype safe to change. Add a real test runner and CI so
every change is checked automatically — the engineering work deliberately
deferred during the v0.1 push.

## Goal & why

Right now verification is manual (`typecheck` + `lint` + `build` + the agent's
`npm run smoke`). That's fine for one author but brittle as the surface grows
(persistence, charts, real connections are all coming). This version makes
correctness **automatic and enforced**, so later milestones can move fast without
regressing the v0.1 contract.

## Scope

- **Web unit tests — Vitest + React Testing Library** (jsdom env):
  - `useThreads` stream mapping — feed a scripted sequence of Mastra chunks
    (`text-delta`, `tool-call`, `tool-result`, `finish`) through a mocked
    `processDataStream` and assert the resulting thread/message state (answer
    text, the thinking timeline, the result card).
  - `isSqlResult` shape detection (`types.ts`) — positive/negative cases.
  - `ResultCard` rendering — table vs. two-column-numeric bar chart.
  - `Composer` — send on submit, and the **Stop** affordance while streaming.
- **Agent tests — promote `db/smoke.ts` into real tests** (still **no LLM**):
  - `assertReadOnly` — accepts `SELECT`/`WITH`; rejects DML/DDL, multiple
    statements, comments-only, and empty input.
  - `listTables` / `describeTable` / `runReadOnlySql` against a freshly seeded
    temp `warehouse.db`.
  - Pick the lightest runner that fits the agent's setup (Vitest, or
    `node:test`); keep `npm run smoke` working as the quick manual check.
- **CI — GitHub Actions** (`.github/workflows/ci.yml`), on push + PR:
  - Root: `format:check`, `typecheck` (both apps), `lint`.
  - Web: `build`, unit tests.
  - Agent: `seed` then tests / `smoke`.
  - Install each app separately (they're standalone, non-workspace projects); use
    npm caching.
- **Scripts** — add `test` (and `test:watch`) to each app and a root `test` that
  delegates into both.

## Out of scope

- E2E / browser tests (Playwright) — revisit once persistence (v0.3) gives stable
  state to assert against.
- Coverage gates / required-check enforcement — start by making CI _exist_ and be
  green; tighten later.
- Any product behavior change — this version adds no features.

## Technical notes

- Vitest fits the existing Vite setup with near-zero config; reuse
  `resolve.tsconfigPaths` so tests can import via `@/`.
- Keep all agent tests LLM-free (the v0.1 split of `db/queries.ts` from `tools/`
  exists precisely for this).
- The pre-push hook can stay as `typecheck + lint`; CI is the backstop that also
  runs the test + build matrix.

## Done when

- `npm test` passes locally in both apps.
- A PR shows a green **CI** check that runs format/typecheck/lint/build + tests.
- The `useThreads` chunk-mapping and `assertReadOnly` guard both have tests that
  fail if their behavior regresses.
