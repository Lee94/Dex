# v2.2.0 — Charts & viz 📋 Planned

**Theme:** Charts as first-class **notebook cells** with agent-chosen
visualization — building on the result-card charts from v0.5.

## Goal

Charts as **first-class notebook cells** with an agent-chosen visualization,
reusing the v0.5 chart primitives.

## Why

v0.5 ("Richer results") puts chart-type selection + line/area on the thread's
**result cards**. v2.2 brings charts **into the notebook as cells** the agent can
create and configure (the product of Hex's `DelegateToVisualizationAgent`), so an
analysis document carries real, re-runnable visualizations next to its SQL.

## Scope

- **Chart cell** — a cell that visualizes another cell's output; chart-type
  selection (table / bar / line / area) and basic encodings.
- **Agent chart authoring** — a `create_chart_cell` step where the agent picks a
  sensible chart for the data shape, reusing the v0.5 chart primitives.
- **Embeds** — chart cells embed in thread answers via `[cell:<id>]`, exactly like
  SQL/semantic cells.

## Out of scope

- **A separate visualization sub-agent** → [v1.2](./v1.2.0-specialized-agents.md)
  (here the main agent picks a chart inline).
- **Heavy BI** (drill-down, cross-filtering) — that's the Canvas direction
  (icebox).

## Technical notes

- Depends on the v0.5 chart rendering and v2.1 cell-kinds. A chart cell references
  an upstream cell's `outputName`/result and stores a small viz config; colors come
  from `--dex-chart-*` tokens (no hardcoded hex).

## Acceptance criteria

- [ ] The agent creates a **chart cell** over a SQL/semantic cell's output with an
      appropriate **default chart type**.
- [ ] The chart cell **renders in the editor** and **embeds in the thread** answer
      via `[cell:<id>]`.
- [ ] Chart type can be switched (table / bar / line / area), reusing v0.5
      primitives; colors come only from `--dex-chart-*` tokens.
- [ ] **Verification green:** web `typecheck` + `lint` + `build`.
