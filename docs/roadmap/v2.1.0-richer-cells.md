# v2.1.0 — Richer cells & cell ops 📋 Planned

**Theme:** Extend the notebook past SQL cells — **semantic** and **markdown**
cells — and let the agent **manage** the cells it created.

## Goal

Round out the notebook past SQL cells — **semantic + markdown** cells — and let
the agent **manage** cells and **build on their outputs**.

## Why

v2.0 shipped SQL cells and the full Hex authoring model (the agent writes cells
into a thread's notebook, chains them by `outputName`, and embeds outputs with
`[cell:<id>]`). The deferred cell types and cell-management round the notebook out
toward Hex (`CreateSemanticTable`, markdown cells, editing/positioning,
`CellSearch` outputs).

## Scope

- **Semantic cell** (Hex `CreateSemanticTable`) — a `create_semantic_cell` tool
  producing an embeddable/editable cell over the v0.4 semantic model
  (cube/measure/dimension), carrying the **"Trusted definition"** provenance.
  Upgrades today's "`query_semantic` returns a card" into a real, re-runnable
  cell.
- **Markdown / text cell** — agent- and user-authored prose cells (reuse
  `Markdown.tsx`) so a notebook reads as a document, not just queries.
- **`read_cells` reads outputs** (Hex `CellSearch` outputs) — the agent can read
  an upstream cell's latest **result**, not just its SQL, so chained reasoning
  builds on actual values.
- **Agent cell ops** — edit / delete / reorder existing cells via tools, plus the
  full `location` placement set (before/after/child/top/bottom).

## Out of scope

- **Python cells / dataframe mode** → [v2.3](./v2.3.0-python-kernel.md) (needs a kernel).
- **Chart cells** → v2.2.
- **Cross-notebook context** (Hex `ExploreProjects`) — later.

## Technical notes

- Extend `CellKind` to `'sql' | 'semantic' | 'text'`; the notebook editor and the
  ThreadView embed renderer branch on kind. Persistence is already a JSON
  document, so new kinds are additive (no migration).
- Semantic cells run via `runSemanticQuery`; the read-only guard is unchanged.

## Acceptance criteria

- [ ] A notebook holds **SQL + semantic + markdown** cells, all authorable by the
      agent and editable by the user.
- [ ] **`create_semantic_cell`** produces an embeddable/editable semantic cell
      carrying the **"Trusted definition"** provenance.
- [ ] The agent can **edit / delete / reorder** cells, and **read an upstream
      cell's output** (not just its SQL) to chain on it.
- [ ] **Verification green:** `npm run smoke` covers semantic-cell creation +
      chaining on a cell's output; both apps `typecheck` + web `build`.
