# v0.1.0 — Threads MVP ✅ Shipped

**Theme:** Ask a data question in plain language; an AI agent explores a SQL
warehouse, **shows its work step by step**, and answers with text + result cards.

This is the first milestone: Hex-Threads-style agentic data analysis, end to end,
wired to the live agent — plus a frontend-engineering pass that turned the fast
MVP UI into a properly-structured codebase.

## What shipped

### Agent backend — `apps/agent` (Mastra + Claude)

- **The `analyst` agent** (`src/mastra/agents/analyst.ts`) — instructions, model,
  three tools, and Mastra `Memory`. Registered under the key **`analyst`** in
  `src/mastra/index.ts` (the exact name the web client addresses).
- **The Anthropic provider** (`src/mastra/model.ts`) — uses `@ai-sdk/anthropic`
  **directly** (not Mastra's model-router string, which fails in offline/
  restricted environments) and **normalizes `ANTHROPIC_BASE_URL` to `/v1`** so
  requests don't 404.
- **Three SQL tools** (`src/mastra/tools/`), thin wrappers over the query layer:
  `list_tables`, `describe_table`, `run_sql`.
- **The warehouse logic** (`src/mastra/db/queries.ts`), kept separate from the
  tools so it's testable without the LLM: `listTables`, `describeTable`,
  `runReadOnlySql`, and **`assertReadOnly`** — the guard that enforces a single
  `SELECT`/`WITH` statement and rejects all DML/DDL.
- **Sample data** (`src/mastra/db/seed.ts`) — a small e-commerce schema
  (`customers`, `products`, `orders`, `order_items`) in a bundled SQLite
  `warehouse.db`, so there's zero external setup.
- **Non-LLM smoke test** (`src/mastra/db/smoke.ts`, `npm run smoke`) — exercises
  the query layer + the read-only guard without an API key.

### Web frontend — `apps/web` (React + Vite, Blueprint "Dex" design)

- Implements the **`Notebook.dc.html`** Claude Design handoff: the app shell
  (sidebar, nav, recents), the **Threads list**, and the focused **thread chat**.
- **Live agent stream wiring** (`src/hooks/useThreads.ts`) — the heart of the app.
  Maps Mastra stream chunks onto UI state: `text-delta` → the answer;
  `tool-call`/`tool-result` → the collapsible **"thinking" step timeline**; a
  `run_sql` result (shape-detected by `isSqlResult`) → a **`ResultCard`** (a table,
  or a bar chart for two-column numeric results).
- **Soft-stoppable streaming** — the SDK client stream takes no abort signal, so
  **Stop** ignores further chunks and best-effort cancels the response body.

### Frontend engineering pass

- **Tooling** — Prettier + oxlint + husky/lint-staged at the repo root;
  **pre-commit** formats staged files, **pre-push** runs `typecheck + lint`.
- **Styling system** — CSS Modules over a token layer: `src/styles/theme.css`
  defines `--dex-*` semantic tokens mapping the design's literals onto the
  vendored Blueprint `--bp-*` vars. **No hardcoded hex in components.** Reusable
  primitives live in `src/components/ui/` (`Button`, `IconButton`, `Pill`,
  `Avatar`).
- **DX & robustness** — the `@/` path alias, typed env + centralized `config.ts`,
  an `ErrorBoundary`, and `React.lazy` code-splitting of the heavy thread view.

## Verification (the "test suite" today)

- Root: `npm run format:check`, `npm run typecheck`, `npm run lint`.
- Web: `npm run build`.
- Agent: `npm run seed` then `npm run smoke`.
- Manual: run both dev servers, open the UI, ask _"Top 5 products by revenue"_,
  confirm thinking steps → answer → result card stream in, and test **Stop**.

## Known gaps (addressed by later versions)

- **Threads are in-memory only** — lost on refresh → **v0.2.0**.
- **Only the bundled SQLite sample data** → **v0.3.0**.
- **No trusted metric definitions** — the agent re-derives SQL on every question →
  **v0.4.0**.
- **One fixed visualization** (table / bar chart, auto-chosen) → **v0.5.0**.
- **No automated tests / CI** → **v1.0.0**.
- **Thread chat only — no editable notebook** → **v2.0.0**.
