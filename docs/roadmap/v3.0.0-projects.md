# v3.0.0 — Projects + Threads pivot ✅ Shipped

**Theme:** Simplify Dex to **two concepts** — **Threads** (conversations with the
agent) and **Projects** (containers that group threads and give them shared
context). Remove the notebook surface entirely; keep the agent's rich results
(tables + charts) inline in the thread.

## Why

The notebook track (v2.0 spike + the deferred v2.1–v2.3 expansion) added a second,
heavier mental model on top of threads, and the sidebar's "Projects" entry actually
pointed at notebooks — conceptually muddled. The product direction is now a clean
two-concept model: a **Project** is a folder of **Threads** with shared standing
context, mirroring how analysts actually organize work.

## What shipped

- **Notebook removed.** Deleted the standalone notebook editor (`/notebooks`
  pages, "Open as notebook"), the cell document store (`dex_notebooks`),
  notebook routes, cross-cell chaining (`resolveChainedSql`), viz-cell
  persistence, and `CellSearch`.
- **Results stay inline, charts kept (decoupled).** The agent's durable "cells"
  became ephemeral conversation results: `CreateSqlCell → ShowSql`,
  `CreateSemanticTable → ShowSemanticTable`, `create_viz_cell → build_chart`
  (validate + return only, no persistence). The thread renders tables
  (`ResultCard`) and charts (`components/thread/ThreadChart.tsx`, the read-only
  vinci viewer extracted from the old viz cell) straight from the stream;
  embeds use `[result:<id>]`.
- **Projects.** A new container with name, description, and **shared context**
  (project-level instructions + bound data sources its threads inherit). Backed
  by `dex_projects` + root `/projects` REST routes; UI at `/projects` (grid) and
  `/projects/:id` (editor + thread list).
- **Thread ↔ project membership** lives in **Mastra thread metadata**
  (`{ projectId }`) — no join table. `updateThreadMeta` is the single writer;
  `listProjectThreads` lists a project's threads via a metadata-filtered memory
  query. Threads can be loose (no project).
- **Shared-context injection.** On a thread's **first message**, the project's
  instructions + bound data sources are folded into the message preamble
  (`contextPrefix(attachments, project)`), reusing the v0.7 attachment system;
  Mastra memory replays it for the rest of the conversation. No change to the
  agent stream contract.
- **Tasks simplified** to SQL-only (the notebook-cell task kind was removed).

## Out of scope / deferred

- Moving an existing thread into a project from the thread UI (the data layer
  supports it via `moveThreadToProject`; no thread-side affordance yet).
- Project-level instructions taking effect retroactively on a thread's later
  turns if the project changes after the first message (injection is first-turn).
- A sidebar tree of projects → their threads (nav links to `/projects` only).

## Done when

- [x] Notebook surface + machinery removed across both apps; no `notebook`/`cell`

- [x] Threads still render tables + charts inline; `[result:<id>]` resolves.
- [x] Projects CRUD (list/create/edit/delete) + shared context (instructions +
