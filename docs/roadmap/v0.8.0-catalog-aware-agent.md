# v0.8.0 — Catalog-aware agent ✅ Shipped

**Theme:** Close the loop on v0.6/v0.7 — feed the curated catalog (descriptions,
endorsements, "exclude from AI") to the agent's discovery tools, and let the
agent discover and target data sources on its own.

## Goal

Make the agent **use the curated catalog** (descriptions, endorsements,
`includedForAi`) in its discovery tools, and let it **discover and target data
sources on its own**.

## Why

v0.6/v0.7 collected real human curation — table/column **descriptions**,
**endorsed** status, an **`includedForAi`** flag — and a multi-source registry.
But the agent's `list_tables` / `describe_table` go straight to the connector and
ignore all of it, and the agent can't enumerate the registered sources (it only
learns one when the user attaches it from the composer "+"). The catalog
investment is effectively invisible to the analyst. This milestone makes the
agent _catalog-aware_.

## Scope

- **Surface metadata to discovery.** `list_tables` / `describe_table` return each
  table/column's `description` + `endorsed` (from `db/metadata.ts`), and the
  agent's instructions tell it to prefer endorsed, well-described data. (Hex
  parity: discovery returns descriptions.)
- **Honor `includedForAi`.** Tables/columns flagged "exclude from AI" are hidden
  from the agent's discovery output and never suggested for querying.
- **`list_datasources` tool** (Hex `ListDataConnections`) — the agent enumerates
  registered sources (id, dialect, label) and targets any via the existing
  `datasourceId`, instead of depending on a composer attachment.
- **`get_current_datetime` tool** (Hex `GetCurrentDateTime`) — current date/time
  for relative-date reasoning ("last 30 days").
- **Scalable discovery (stretch).** Keyword table search for large warehouses
  (Hex `FindTableSchemas`) once table count exceeds `list_tables`' enrich cap.

## Out of scope

- **Vector/semantic column search** (Hex `FindSemanticColumns`) — needs embedding
  infra; deferred to a later platform milestone.
- **Editing metadata from the agent** — curation stays a Data-browser (UI)
  concern; the agent only _reads_ it.
- **Switching the active/default source at runtime** — unchanged from v0.7.

## Technical notes

- The overlay already lives in `dex.db` (`dex_table/column_metadata`); the tools
  merge it into their output and apply the `includedForAi` filter. Thin
  `createTool` wrappers, no stream-contract change, read-only guard intact.
- `list_datasources` reuses the v0.6 registry (`loadAllConfigs` +
  `getBuiltinDataSource`); `get_current_datetime` is a pure helper.

## Acceptance criteria

- [x] `list_tables` / `describe_table` include each table/column's **description**
      and **endorsed** status from the metadata overlay.
- [x] Tables/columns flagged **`includedForAi = false` are omitted** from the
      agent's discovery output and never suggested for querying.
- [x] The agent can call **`list_datasources`** and run a query against a
      non-builtin source **without** a composer attachment.
- [x] **`get_current_datetime`** returns the current date/time and the agent uses
      it to answer a relative-date question ("last 30 days").
- [x] **Verification green:** `npm run smoke` covers metadata-enriched discovery +
