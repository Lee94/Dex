# v3.5.0 — Collaboration 📋 Planned (strategic)

**Theme:** Move Dex from a single-user prototype toward Hex's multiplayer model —
identity, comments, and permissioned sharing. The largest, most strategic gap;
sequenced last and expected to split into sub-milestones.

## Why

Dex is single-user by construction (`CREATOR = 'you@dex.local'`, no auth, no
RBAC). Hex Threads are collaborative: real-time multiplayer, comments, @mentions,
and published/permissioned sharing. This is foundational rather than a thread
tweak, so it depends on the read-only sharing + persistence introduced in v3.4
and should be planned as its own track.

## What ships (to be split into sub-milestones)

- **Identity & permissions:** replace the hardcoded `CREATOR` with real users;
  owner/member scoping on projects and threads (extend `db/projects.ts` + thread
  metadata); auth middleware on the agent + root routes.
- **Comments & @mentions** on threads/results.
- **Permissioned sharing:** extend v3.4's read-only link to role-based access.
- **Real-time multiplayer** (presence, collaborative cursors) — optional, heavy;
  likely a separate milestone.

## Out of scope / deferred

- Org/workspace administration, SSO, audit logs (enterprise scope — icebox).
- Real-time co-editing if it proves disproportionate to prototype value.

## Done when

- [ ] (Sub-milestone 1) Real identity + owner/member permissions on projects and
      threads; routes are auth-gated.
- [ ] (Sub-milestone 2) Comments + @mentions work on a thread.
- [ ] (Sub-milestone 3) Shared links carry role-based access.
- [ ] Each sub-milestone keeps `typecheck` + `lint` + `test` + `build` + `smoke`
      green.
