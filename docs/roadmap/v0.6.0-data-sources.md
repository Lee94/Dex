# v0.6.0 — Data sources & catalog ✅ Shipped

**Theme:** Bring data sources into the product surface. A **Data browser** module
(the "Data" nav) where you register read-only connections, browse their
schema/tables/columns, preview real rows, explore the semantic model, and curate
table/column metadata — implementing the `DataBrowser.dc.html` design.

## Goal & why

Through v0.5 a data source was an _environment variable_: Dex pointed at exactly
one warehouse, chosen by `apps/agent/.env`, with no way to see what was in it
short of asking the agent. v0.3 already put every warehouse behind a clean
`Connector` interface and v0.4 modeled it into a semantic layer — but neither was
_visible_ in the UI. This milestone surfaces both: a real catalog you can open,
drill into, and annotate, plus the ability to **add connections** from the page
instead of editing env. It turns "the agent's database" into a browsable,
curatable asset.

## Scope

- **Source registry** — list the registered data sources (the env-configured one
  appears as a synthetic `builtin` entry tagged as the agent's source) and **add a
  new Postgres / SQLite connection** from a dialog. New connections are
  probe-tested before they persist.
- **Catalog browsing** — drill a source → its schema/table tree (row counts,
  endorsed marks, search) → a table's **columns** (name / type / PK / description)
  and a **preview** of the first 50 real rows.
- **Data Models** — browse the v0.4 semantic model as projects → models, each with
  its measures, dimensions, joins, and a preview; endorsed members are marked.
- **Metadata curation** — edit a table/column **description**, a **status**
  (endorsed), **categories**, and the **Included for AI** flag, persisted and
  merged over introspection at read time.

## Out of scope

- **Letting a runtime source switch drive the agent.** The agent's dialect and
  instructions are fixed at boot (`agents/analyst.ts`, `tools/run-sql.ts` read the
  provider at module load). The browser opens _additional_ read-only connectors
  independently; the agent still queries the env-configured source. Switching the
  agent's active source remains a restart-time concern.
- **`Included for AI` actually gating the agent.** It is persisted and surfaced,
  but does not yet filter what the agent's catalog tools see (deferred — same
  boot-time constraint).
- **Multi-schema sources.** A connector is scoped to one schema; the tree shows a
  single schema bucket (`main` for SQLite, the configured schema for Postgres).
- **Editing the semantic model from the UI** — it stays a typed config (v0.4);
  Data Models is read-only browsing.
- **Snowflake / other engines, secrets management UI, RBAC.**

## Technical notes

- **Independent HTTP routes, not the agent.** The module is served by new
  read-only routes registered on the Mastra server via `registerApiRoute`
  (`server/routes.ts`, wired in `index.ts`). They mount at the server **root**
  (e.g. `/datasources`, `/semantic/projects`) — _not_ under `/api`, where the
  agent's own routes live. This sidesteps the boot-time dialect constraint
  entirely.
- **Multi-source connectors.** `connector.ts` keeps the env singleton
  (`getConnector`, unchanged) and adds a `Map<id, Connector>` with
  `createConnectorFromConfig` / `getConnectorById` / `closeConnectorById`. Both
  connectors gained an optional, backward-compatible parameterized constructor.
- **Never bypass the read-only guard.** Preview is `SELECT * FROM "table" LIMIT n`
  through `Connector.runReadOnlySql` (so `assertReadOnly` + the Postgres read-only
  transaction / `statement_timeout` / row caps all apply); table names are checked
  against `IDENTIFIER` first.
- **Credentials never touch the database.** Non-sensitive params live in a
  dedicated `dex.db` (gitignored, separate from `warehouse.db` and Mastra's
  `mastra.db`); the password / connection string lives in a gitignored
  `datasources.local.json`, and the row only stores a `credentialRef`. API
  responses never echo the secret and mask the host.
- **Reuse over rebuild.** Routes delegate to `Connector.listTables` /
  `describeTable` / `runReadOnlySql` and `describeModelSummary`; the web view
  reuses the `--dex-*` tokens, `components/ui` primitives, and the lazy-loaded view
  pattern. `npm run smoke` covers the connector factory, the registry, the
  metadata overlay, and the preview path.

## Done when

- The **Data** nav opens a Data browser with the env source listed (tagged as the
  agent's source) and an **Add data connection** dialog that registers + browses a
  new Postgres source.
- Drilling a source shows its tables with row counts; opening a table shows its
  columns (with PK + type) and a **preview of real rows**.
- **Data Models** browses the v0.4 semantic model (measures / dimensions / joins).
- Editing a table's description / status / categories / "Included for AI"
  **persists** and is reflected on reload.
- `npm run smoke` passes (existing assertions unchanged = zero regression, plus the
  new connector/metadata/preview checks); typecheck + lint + build are green.
