# v1.2.0 — Specialized agents ✅ Shipped

**Theme:** Move from one analyst to a small **team** — a planner plus specialist
sub-agents (data discovery, visualization), as Hex delegates.

## Goal

Move from one analyst to a small **team** — the analyst **delegates** discovery
and visualization to specialist sub-agents and **synthesizes** the result.

## Why

Hex delegates discovery and visualization to specialized sub-agents, keeping the
main agent focused and enabling parallel work. Dex is a single agent. (This was
the roadmap icebox item "Multiple / specialized agents.")

## Scope

- **Sub-agent delegation** — a **data-discovery** agent (Hex
  `DelegateToDataDiscoveryAgent`) and a **visualization** agent
  (`DelegateToVisualizationAgent`), invoked by the main analyst as tools.
- **Planner (optional)** — orchestrates discovery → analysis → viz for complex
  asks.
- **Parallel discovery** — fan out across sources / semantic / (future) projects.
- **Interruption handling + synthesis** — mid-run user input reaches the running
  sub-agent; the main agent synthesizes results.

## Out of scope

- **Arbitrary user-defined agents / an agent marketplace.**

## Technical notes

- Built on Mastra's multi-agent / workflow primitives. The **web↔agent contract
  holds**: `analyst` stays the registered entry point and the streamed surface;
  sub-agents are internal.

## Acceptance criteria

- [x] The analyst **delegates a discovery task** to a data-discovery sub-agent and
      uses its result (`delegate_to_data_discovery` → `dataDiscoveryAgent`).
- [x] The analyst **delegates a visualization task** to a viz sub-agent (rendered
      via the v0.5 result cards) (`delegate_to_visualization` → `visualizationAgent`).
- [x] A multi-step ask runs discovery → analysis → viz and yields **one
      synthesized answer** (the `<delegation>` instruction).
- [x] **Verification green:** both apps `typecheck` + web `build`; the `analyst`
      registry key + Mastra stream contract are unchanged (a structural test guards it).
